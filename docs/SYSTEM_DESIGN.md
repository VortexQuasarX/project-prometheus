# SYSTEM_DESIGN

## Services (target topology)

| Service | Status | Transport |
|---|---|---|
| API Gateway (FastAPI, `/api/v1`) | ✅ in monolith | REST |
| Auth (API keys + RBAC) | ✅ in monolith | REST headers |
| Policy/Governance engine | ✅ in monolith | REST |
| Agent runtime (FinOps/Reliability) | ✅ in monolith | REST + SSE |
| RAG (chunk→embed→search) | ✅ in monolith | in-process |
| LLM Gateway (provider abstraction: mock/openai/bedrock) | ✅ | in-process |
| ML Inference (router model) | ✅ separate FastAPI app (`ml_service/`) | REST `/predict`, gRPC contract next |
| Evaluation harness | ✅ in monolith | in-process + REST |
| Cost/FinOps | ✅ in monolith | REST |
| Event pipeline (Kafka-style outbox → consumers → DLQ) | ✅ code + in-memory verified | Kafka (live broker NOT VERIFIED) |

Rule from the mission: no meaningless splits — the ML inference service is
extracted because it has independent scaling/versioning needs; everything else
stays in the gateway monolith until load data justifies a split.

## Data layer

- SQLite (WAL) local; **PostgreSQL/Aurora** production (SQLAlchemy-portable,
  `DATABASE_URL`-driven). Measured boundary: SQLite single-writer fails at ~25
  concurrent writers (docs/LOAD_TESTING.md).
- Alembic migrations: `alembic upgrade head` (autogenerated initial schema,
  VERIFIED on SQLite).
- Redis: reserved for distributed rate-limit/state (V2, env `CACHE_PROVIDER`).

## Request path (chat)

auth → rate limit → budget/kill-switch → guardrails (PII mask/block) →
router (heuristic; learned model in ML inference) → semantic cache →
RAG → LLM provider → evaluator → cost ledger → audit → response.
12 canonical trace events + SSE outbox events per request.
